# Platform (stage 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a full software stack practical inside a world: agents' own HTTP(S) clients reach world services
through a recording proxy, stacks are saved at fork points and run end instead of after every write (with cheap
per-volume strategies in `service`), and parts get the world clock so telemetry can be stamped with world time.

**Architecture:** A new shaked listener (`proxy/`) accepts plain-HTTP and `CONNECT` requests from drivers and agents,
terminates TLS with a per-branch CA for the hosts the world's parts declare (new optional protocol method
`http_routes`), forwards to the part's upstream behind the branch gate, and records each request as a `tool_call`
step named `http` owned by that part. Parts may declare `save_at: "points"`: shaked then saves them only at save
points (before a model call through the gateway, on request, at run end), recorded as a new `save_point` event, and
a fork whose point has no save moves back to the last one. Parts get `world_time {epoch_ms, speed}` at `start`;
the kits turn a clock into stamps.

**Tech Stack:** Rust (axum 0.8, hyper 1, hyper-util, tokio-rustls 0.26, rcgen, reqwest 0.12), Python 3 (kit, SDK,
toy fixtures), React + TypeScript + vitest (two small UI changes), Docker Compose (`service`).

**Spec:** `docs/superpowers/specs/2026-11-19-software-factory-design.md` (Goal 2; "Calls made after the builder check":
Proxy routing, Saves). Client facts: `docs/superpowers/research/2026-11-19-twin-endpoints.md` (§0 D1/D5, §2.1, §3.1,
§3.4, §6.2).

## Calls made

| # | Call | Why | Cost if wrong |
|---|---|---|---|
| C1 | **HTTPS is in this stage** (coordinator input 2026-11-19): `CONNECT` to a declared host on 443, TLS terminated with a per-branch CA (rcgen), leaf per host, ALPN `http/1.1`. Drivers and agents trust it through `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`, `NODE_EXTRA_CA_CERTS`, `GIT_SSL_CAINFO`. | `gh` talks only https on 443 to a GHES host; PyGithub asserts scheme/host/port of every returned URL (research §2.1, §3.1). | One more crate (`rcgen`); a client that pins its own trust store ignores the env and fails TLS. |
| C2 | Hosts are declared **per instance** by a new optional method `http_routes {instance}` → `{routes: [{host, upstream, env?, reads?}]}`; `-32601` means "serves none". Not in `describe`. | Host names come from the part's config (template data) and upstream ports from the running instance. Host names never include branch or instance ids, so they are stable across runs and forks. | One extra round trip per part at world start. |
| C3 | Absolute URLs: the proxy keeps `Host: <world host>` and adds `X-Forwarded-Proto`, `X-Forwarded-Host`, `X-Forwarded-Port`. A part builds every absolute URL from those (kit helper `public_base`), never from its upstream address. | PyGithub/Jira dereference returned URLs (research D5). | A twin that ignores the headers breaks PyGithub; stage 4 tests catch it. |
| C4 | A proxied request is recorded as a `tool_call` named `http` (args = request, result = response, `part` = owner, keys `http/<host>`). `http` becomes a reserved tool name. | Saves, forks, timeline, compare and the step drawer already treat tool calls as steps. | A richer HTTP view later reads the same payload. |
| C5 | Effect: GET/HEAD/OPTIONS read, other methods write, unless the route's `reads` patterns match (`POST */git-upload-pack`) or the upstream answers with header `X-Shakedown-Effect: read|write` (stripped before the client sees it). GraphQL bodies are recorded like any POST. | git fetch is a POST; a GraphQL twin knows a query from a mutation, the proxy can't. Under save points a write mislabelled read is never saved, so the part has the last word. | A twin that never sends the header gets every GraphQL query counted as a write (extra saves, nothing wrong). |
| C6 | A proxied request holds the branch gate while in flight, as tool calls do. | World order, saves and event order agree; a save never overlaps a request. | Parallel agents' HTTP requests serialize per branch; a long clone delays others. |
| C7 | Bodies are kept as text up to 64 KiB, else `{bytes, sha256}`; requests over 256 MiB get 413. Recorded HTTP steps are never sent again: a part that serves HTTP must restore from saves (a part with `exact: "replay"` and routes is refused). | Forks restore parts from saves; git packs are large and binary. | No replay mode for HTTP twins. |
| C8 | The proxy env is given **only when the world has routes**. Unknown hosts are refused (403) and recorded. | Existing drivers that call providers directly keep working; a world with routes is sealed (spec). | None for today's benchmarks. |
| C9 | Proxy auth: a random ticket in the proxy URL (`http://shakedown:<ticket>@127.0.0.1:<port>`) → (branch, agent?). Agents' tickets (in their register answer) attribute exactly; the driver's ticket attributes to the agent of the branch's latest gateway model call (`args.attributed: "latest model call"`), else none. Listener on 127.0.0.1, `SHAKEDOWN_PROXY_PORT` (default: a free port). | One listener for all branches; in-process multi-agent drivers rarely set per-agent proxies. | Parallel agents in one driver process may be attributed to the wrong one. |
| C10 | **Save points.** `describe.save_at: "step"` (default, today) or `"points"`. A points part is saved before a model call through the gateway when it changed since its last save, on `POST /api/branches/{id}/save`, and at run end. Each is a `save_point` event `{reason, saves, error?, paused_ms}`. A fork whose restore lacks a save moves back to the latest model call or agent start that has one, reason `REASON_SAVED`. | Forks already start at model calls (a tool-call fork is redone from the model call that chose it), so the world is restorable exactly where forks start: N writes between model calls cost one save, reads none, a clock part at most one per model call. | Clients that report usage instead of using the gateway get no save points; their forks move further back. |
| C11 | `service` volume strategies: `tar` (default; old configs unchanged), `postgres` (plain `pg_dump` while running, `psql` on restore before the other services start), `hardlink` (`rsync --link-dest` between the instance's saves, in `rsync_image`, which is required for it), `skip` (created empty). A file volume may name the compose `services` to stop while it is copied; otherwise the whole project stops, as today. Save bytes count each inode once. | Stopping the whole stack per save restarts production and fakes incidents; hard links only work between saves (a docker volume and `SHAKEDOWN_SAVES` are different mounts). | `hardlink` needs an image with rsync on the machine (never pulled). |
| C12 | **World time.** Epoch = the task's `clock_start` read as UTC, else the run's start; recorded in `RunStart.world_epoch_ms` (runs without it: their `RunStart.at`). Parts get `world_time {epoch_ms, speed}` in `start`; drivers get `SHAKEDOWN_WORLD_EPOCH_MS`, `SHAKEDOWN_CLOCK_SPEED` and `GET /api/branches/{id}/clock`. Kit `WorldTime`: stamp = epoch + clock_ms; between advances it runs on at `speed`, at most 1 s of world time past the last clock seen, and never backwards. | Pauses (saves, flow) never reach a part except as a clock that stood still. Stage 4 builds the exporters (remote-write, Loki push, OTLP); stage 2 gives the time and the stamp formats. | Telemetry may lag world time by up to one tick (200 ms) during a pause. |
| C13 | Claude Code / Codex CLI sessions get no proxy env in this stage. | Stage 5 designs run as drivers. | CLI agents reach world HTTP only through MCP tools. |

## Global Constraints

  time; vitest `--maxWorkers=1`. Redirect long output to a file and read its tail.

  (`shaked`, `parts`; `parts` depends on the kit by path, so a proto change rebuilds both).

  `cargo test --workspace --no-fail-fast`; `uv run pytest -q` in each Python package touched; in `ui/`, `npx tsc -b`
  and `npx vitest run --maxWorkers=1`. Postgres for core tests: container `deploy-pg-1` on 127.0.0.1:5544
  (`docker start deploy-pg-1` if refused).
- clippy caps functions at 30 lines (`too_many_lines`, `-D warnings`).
- Existing behaviour stays: every existing test passes unchanged. New persisted fields get `#[serde(default)]`;
  new wire fields are optional and skipped when empty, so old parts, old runs and old answers read as before.
- New dependencies: `rcgen` (Task 5); `hyper`, `hyper-util`, `http-body-util`, `tokio-rustls`, `bytes`, `base64`
  as direct deps of `shaked` (already in `core/Cargo.lock`). No others.
- Do not rename `shakedown`/`SHAKEDOWN_*` identifiers. No hardcoded domain data: host names and base-URL env come from part
  config, never from shaked code; test hosts are `*.test` fixtures.
- Commit messages: plain sentences in the repo's style, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Do not push.

## Review Focus

1. A large `POST` from git or curl with `Expect: 100-continue` and chunked bodies goes through and is recorded with
   its size and hash (Task 3 test `a_large_post_with_expect_continue_goes_through`).
2. The upstream sees the world's host name and the forwarded scheme/host/port, over plain HTTP and over TLS, so a
   twin mints URLs clients accept (Task 3 `the_upstream_sees_the_worlds_host_name`, Task 5
   `https_forwarding_says_https_on_443`).
3. A branch paused or ended while a proxied request waits: held while paused, 409 once the run ended, never a hang
   (Task 3 `a_paused_branch_holds_requests_until_it_resumes`).
4. A `save_point` event is never a step: metrics, compare's divergence, review citations and the UI's step lists are
   the same with and without it (Task 6 `a_save_point_is_no_step`, Task 9 test).
5. Runs and parts from before this stage: no `world_epoch_ms`, no `save_at`, no `http_routes`, `service` configs with
   plain volume names — they start, fork and save exactly as before (Task 6 `a_step_part_is_still_saved_after_each_write`,
   Task 7 `plain_volume_names_save_as_before`, Task 8 `a_run_recorded_before_world_time_takes_its_start_as_epoch`).

  `Write requests are not available to this agent: its team made it read-only` (recorded); 502
  `the {part} part did not answer at {host}: {err}` (recorded); 413 `the request body is over 256 MiB` (recorded).
