# Editors Implementation Plan (3b)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Worlds, scenarios, agent setups and experiments are created and edited in the app, on settings-style pages that write their project files. Each page shows one section at a time, has label-left rows, and a save bar that appears after a change.

**Architecture:**
- One generic layer over `api/project.ts`:
  - `useItemEditor(kind, id)` holds the loaded body, a draft, `dirty`, save (a put with confirm), discard and the file's problems.
  - `ItemListPage` lists a kind and creates new items from a minimal template.
  - `EditorFrame` holds the header, the SubNav, the section and the save bar.
- Each kind gets its sections as small components over the typed body. Editing is pure updates of the draft (`set(path, value)` helpers in `edit.ts`), unit-tested without a page.

**Tech Stack:** React 19, the plan 2 components (Card, SubNav, SaveBar, FormRow, Toggle), vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-20-primitives-and-editors-design.md` §3 (configuration pages), §1 (what each primitive holds), §14b (no paths; blank by default).

## Global Constraints

- **Code quality:** lint at zero warnings, functions of 40 lines or fewer, the build passes, `npm test` passes, no `any`, one component per file over about 60 lines.
- **Blank by default:** a page opens on Overview with nothing dirty. New items start from a minimal valid template with empty optional fields, and no option is preselected beyond what the format requires.
- **No paths:** show names and ids only.
- **Saving:** puts send `confirm: true` (the person saving is the confirmation). A 422 shows its message and JSON pointer next to the save bar and keeps the draft.
- **Secrets:** fields for credentials take a key-store name or an environment variable name, never a value. Placeholders say so.

## Review Focus

1. **A 422 on save** (for example an inline credential, or an event with neither time nor call count): the draft is kept and the message is shown (Task 1 test `save_error_keeps_draft`).
2. **Leaving with unsaved changes:** Discard restores the loaded body exactly (Task 1 test `discard_restores`).
3. **A new item whose id is taken:** refused before writing, with "An item named … already exists" (Task 1 test `new_item_id_taken`).
4. **Invalid ids** such as `My World` are refused in the New dialog with the id rule (Task 1 test `new_item_bad_id`).
5. **A world with a runtime package removed:** the editor shows "No runtime yet" on Overview, not an error (Task 2 test `world_without_package_overview`).

**Sections:**
- **Overview:** a timeline of events by world time; events fired by a call count are listed apart.
- **Inputs:** world select, preset task, the ticket (a textarea), and starting changes (record, value).

- **Checks:** text, Goal or Safety, and an "Ends the run when true" switch.
